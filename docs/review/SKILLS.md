# AnyDatas 提炼技能与可复用范式

- 更新日期: 2026-07-26

本文有两部分：(A) 为本仓库落地的 **Claude Code 技能**（可被 `/<name>` 或自动触发调用）；(B) 从代码库提炼、**可迁移到其他项目**的工程范式。

---

## A. 已落地的 Claude Code 技能（`.claude/skills/`）

| 技能 | 何时触发 | 作用 |
| --- | --- | --- |
| **anydatas-dev** | 让「运行/启动/构建 app」「复现 bug」「跑测试/lint」「本地看生产包」 | 本地双终端 + Docker 的构建/运行/验证命令、运行时开关、健康探针、以及「别跑遗留 Python」等坑位 |
| **anydatas-backend-patterns** | 写/评审 `backend/` 代码：加端点、迁移、查询路径、后台任务、Agent 工具 | 把租户隔离、`AppError`、许可移入 blocking、SQL 安全、UUID 路径校验、测试夹具等既有原语固化为可照抄的规范 |
| **anydatas-review** | 评审 PR/diff 或提交前自检 | 按改动区域分组的「本仓最易破坏的不变量 + 已知脆弱点」清单，与通用 `/code-review` 配合 |

这些技能把本次评审沉淀的知识变成**可执行、可复用**的形态：下次有人动这块代码，技能会主动提醒既有约定与已知坑，而不必重新审一遍。

## B. 可迁移的工程范式（这套代码值得抄的做法）

以下每条都源自本仓库的真实实现，抽象成与具体框架无关的模式，可用于任何「单机/自托管、含后台执行与外部 LLM 调用」的服务。

### 1. 许可移入阻塞线程，让超时不破坏并发上限
并发用 `OwnedSemaphorePermit` 而非「进函数拿、出函数放」。把许可 **move 进** `spawn_blocking` 闭包，则 HTTP 侧超时提前返回客户端时，真正在跑的重活仍持有槽位——避免「客户端重试风暴 → 实际并发远超配置 → 主机被拖垮」。
> 来源：`resource_control.rs` / `execution.rs`。适用：任何「超时可能早于底层工作结束」的资源受限系统。

### 2. 内容寻址缓存 + 版本号换键
昂贵派生物（这里是解析后的 DuckDB 表）以「输入内容哈希」为文件名，首算即缓存、后续免算；输入的**配置版本**变化就换新键，从而「在途读者永远读到自洽快照，写者永不覆盖在读的文件」。配合弱引用 per-key 互斥：同一输入只算一次，不同输入并行。
> 来源：`query_engine.rs`。**教训**：哈希多个变长字段务必**域分隔**（长度前缀），否则碰撞（本仓 M6）。

### 3. 崩溃安全物化：临时文件 → CHECKPOINT → 原子重命名
任何「生成一个文件制品」的路径都写临时文件、落盘、再 `rename` 到最终名。崩溃只会留下可被 GC 的临时文件，永不出现「半成品被当成完成品」。
> 来源：缓存与 job 制品。适用：任何生成缓存/导出/快照的系统。

### 4. 状态权威在 DB，事件总线只做唤醒
长任务/流式场景：**SQLite 是唯一事实源**，进程内事件总线只传「版本号」通知订阅者回库读完整快照。于是刷新/重连/断线总能恢复，空闲的 SSE 连接不碰 DB，且不依赖 Redis/pub-sub。
> 来源：Agent Runtime（`agent.rs` + `AgentEventHub`）。适用：任何需要「可恢复的实时进度」的功能。

### 5. 启动即和解在途状态
进程启动时把「重启前残留的 running/queued」统一收敛为 `failed`（幂等），UI 不会永久卡住，也无需分布式租约。单实例语义下这比复杂的心跳检测简单且可靠。
> 来源：`recover_interrupted_jobs`/`recover_interrupted_agent_runs`。**边界**：仅适用于单实例；多实例需实例锁。

### 6. 原子认领 + 状态守卫的 SQL 队列
无消息队列也能做可靠后台执行：`UPDATE ... WHERE id=? AND status='queued'` 认领（查 `rows_affected`），终态写入带 `WHERE ... AND status='running'` 守卫防竞态覆盖。partial unique index 在 DB 层编码「一实体一活跃任务」。
> 来源：`workers.rs` + migration。**教训**：认领后的每条错误路径都必须落终态，否则卡 running（本仓 M8）。

### 7. LLM 上下文的确定性预算
长对话压缩用**规则**而非再调一次模型：固定规则、事实、摘要、近期消息各占明确额度，总量硬上限，优先保留最新用户需求。避免额外费用、递归超时和「摘要幻觉改写事实」。
> 来源：Agent 滚动摘要。适用：任何长上下文 Agent。

### 8. LLM 工具 = 显式注册 + 只读 + 服务端二次裁剪
Agent 工具只用**静态注册**的白名单（name/description/JSON Schema），全部只读，参数完整拼接后才校验，未知工具/坏参数作为「失败观察」回给模型自我修正——绝不动态派发代码。喂给模型的数据在服务端二次裁剪，绝不塞原始文件/整表/服务器路径/缓存键。
> 来源：`preview_sql`/`inspect_table`。适用：任何给 LLM 工具的系统（防 prompt 注入放大为真实副作用）。

### 9. SSRF 纵深防御（可直接抄的清单）
禁重定向 + DNS 解析后**逐个 IP** 校验 v4/v6 全部保留网段（loopback/私网/link-local/CGNAT `100.64/10`/文档段/IPv4-mapped）+ 公网强制 HTTPS + 拒绝 URL 内嵌凭据 + 私网访问需**部署者**显式开关（普通管理员不能自行放开）。
> 来源：`agent_provider.rs::validate_base_url_network`。**未竟**：还需把出站连接**钉到已校验 IP** 以堵 DNS-rebinding（本仓 M1）。

### 10. 集中校验 + 统一错误面 + 一致安全边界
所有配置在启动时**区间校验、越界即拒启动**（`config.rs`）；所有 handler 返回统一 `AppResult`，内部错误脱敏为 500 且打日志；租户隔离在 SQL 层用一个 helper 强制（`(? IS NULL OR workspace_id=?)`），执行路径无法绕过。安全边界只有一处、被到处复用。
> 来源：`config.rs` / `error.rs` / `db.rs`。适用：几乎所有服务——把「边界」做成单一可复用点，比在每个 handler 重复更难出错。

### 11. 「保留计划、标注已落地」的文档纪律（含反面教训）
路线图文档保留、另有一组文档标注「实际运行的是什么」。**但要加醒目分隔**——本仓 `docs/00–10` 的旧愿景与 `docs/13–17` 的现状混排，新人读 `docs/04` 会被误导（本仓文档漂移发现）。可迁移做法：在每个「愿景/历史」文档顶部加一行「⚠️ 本文为历史规划，当前实现见 X」。

## 如何使用本文

- 想跑/改/评审 AnyDatas → 直接触发 A 部分的技能（或 `/anydatas-dev`、`/anydatas-backend-patterns`、`/anydatas-review`）。
