# AnyDatas 前端 UX 评审

- 评审日期: 2026-07-26
- 范围: 前端全部界面（登录/初始化、数据分析工作台、AI Agent、后台任务、导入弹窗、检查器）
- 方法: 精读真实渲染截图（登录 / 明暗两版工作台与导入弹窗）+ 可访问性快照 + 组件代码，10 个 UX 维度并行评审并汇总
- 结果: 74 条发现（**22 高 / 33 中 / 19 低**）。本文按「贯穿性主题 → 快速见效 → 高优先级明细 → 中低优先级 → 落地顺序」组织。

---

## 一、总体评价

**底子很好，问题集中在「可读性密度、关键操作可发现性、流程断头路、组件系统一致性」四类，且多为可控的打磨项，而非推倒重来。**

做得好的地方（应保留）：
- **设计令牌系统扎实**：`style.css:1-157` 一套语义化色板（绿色主色 + 面板/表面/线条/文本层级 + 状态色），明暗双主题，Element Plus 变量重映射。截图整体观感冷静、专业。
- **导入确认弹窗是全局亮点**：按 Sheet 勾选、独立起止单元格、类型推断、实时样本预览（见明暗两版截图），一旦文件进来，流程支撑得很好。
- **AI Agent 运行时 UI 强**：持久化 Run/Step 时间线、SSE+轮询降级、逐条候选 SQL（复制/应用/预览/运行）、`aria-live` 流式、表上下文隔离。
- **可访问性与反馈有基线**：`lang=zh-CN`、全局 `focus-visible`、DataGrid 原生表格语义、`role=tablist`/`aria-pressed`、图标按钮多数有 `aria-label`；几乎每个异步操作都 `try/catch + errorMessage()` toast、主按钮绑 `:loading`。

贯穿性问题（下面展开）：字号过小、纯图标动作难发现、几条核心流程「做完不知去哪」、AI 与分析割裂、以及同一控件被重复造 3–4 遍。

## 二、五条贯穿性主题（多维度独立命中 = 真正的优先级）

> 这几条被多个评审维度**各自独立**指了出来，收敛本身就是信号。若只做有限投入，优先解决它们。

### T1 · 可读性：中文界面字号触底到 9–11px
全站 `font-size:9px` 出现 32 处、`10px` 51 处、`11px` 37 处（约 120 条规则把正文/次要文字压到 ≤11px），最小处 8px（`.agent-invalid-table` `style.css:1130`）。中文（CJK）笔画密度高，9–10px 在桌面视距下吃力，叠加 `--muted/--subtle` 灰度后跌破可用对比度。**这是每一屏最大的阅读拖累。** 另有两个放大器：
- **自造字重梯 620/630/650/720/750 在中文字体上无法区分**——`PingFang SC / YaHei` 只有 400/500/600 离散字重且 `font-synthesis:none`，620/630/650 全部塌到 600、720/750 塌到 700，精心设计的层级在中文上根本不显现。
- **浅色 `--subtle` (#8b9892 ≈3:1) 在它被用的小字号上不达标**（WCAG 1.4.3 需 4.5:1），影响登录页元信息、DataGrid 列类型副标题、导入 Sheet 元信息。

### T2 · 可发现性：核心操作藏在无标签图标背后
- **上传**——全产品最重要的首次操作——只是侧栏一个 32px 纯图标按钮（`FileSidebar.vue:306-323`），靠 hover tooltip 提供文字；两处空态都喊「上传」却都不可点。
- **工作台工具栏**四个连排纯图标（`WorkbenchView.vue:264-287`）：Save/Trash/**ListPlus=转后台任务**/**Sparkles=打开 AI**。后两个是产品旗舰能力，却用无约定俗成含义的图标、仅靠 tooltip，首次使用基本发现不了。
- **空态是「非可操作的死胡同」**：中心空态（`WorkbenchView.vue:415-419`）纯文字无按钮，且副标题「展开文件后选择工作表」在 0 文件时是**做不到的步骤**；同屏三处空态（侧栏/中心/检查器）互相指来指去。最响的像素（实心绿上传图标）指向的是次要动作，真正的「从这开始」却是灰色帮助文字。

### T3 · 流程断头路：做完关键动作却不知去哪
- **转后台任务后无导航/无链接**（`WorkbenchView.vue:151-162`）：`createJob` 成功只弹一句 toast 就关弹窗，不跳 `/tasks`、不选中新任务、无入口——恰恰在用户最关心结果的时刻断掉，感觉「像没生效」。
- **多 Sheet 导入只自动绑定默认表**：其余已导入的 Sheet 要回文件树里翻找。
- **应用/运行候选 SQL 会把用户弹出 Agent 页**（见 T4）。

### T4 · AI 与分析割裂
AI 是独立整页路由 `/agent`（`WorkbenchView.vue:78` `router.push('/agent')`），聊天时看不到 SQL/绑定/结果；应用/运行候选 SQL 又跳回 `/workbench`（`AgentView.vue:31,46`），**连纯「应用」（只写入编辑器、不执行）都要跳走**，丢失滚动位置与正在读的时间线。更麻烦的是**存在两套「我在用哪些表」**：工作台 `queryBindings` 与 Agent `agentTableBindings` 相互独立、上限不同（16 张）、默认不同步——绑了 3 张表去开 AI，却发现上下文是「已选 0/3」。上下文状态还分散在三处（侧栏底部 / 头部弹层 / 右侧面板）需用户自己对齐。此外，**改一下选表会冻结整个输入框**（`contextChanged` 置 `:disabled`，`AiAssistantPanel.vue:1062`），逼用户先「新建/恢复」才能继续打字——隔离意图正确，但代价过重、易被读成「输入框坏了」。

### T5 · 组件系统漂移：一个控件造了 3–4 遍
色板层很成体系，但**其下没有强制的字号/圆角/间距/图标尺寸/交互组件规范**：
- **分段切换控件被实现了 4 种**：顶栏 `.workspace-switch`、结果区 `.result-view-switch/.chart-type-switch`、页签 `.analysis-tabs`、Agent 思考等级用 `el-segmented`——各自高度(32/26/44px)/圆角/选中态都不同。
- **方形图标按钮至少 8 种 bespoke 类**（22–32px 不等的命中区与 hover），且**同一角色混用原生 `<button>` 与 `<el-button>`**（焦点环/禁用/loading 行为不一致）。
- **搜索框造了 4 个不同版本**；类型/圆角/间距全是硬编码字面量、无 token。整体读起来像「一套好看的配色，罩在许多各自为政的组件上」。

## 三、快速见效（高影响 / 小工作量，建议第一批）

| # | 改动 | 位置 | 为什么值得先做 |
|---|---|---|---|
| 1 | **日程时区改为对 每天/工作日/自定义 常显**（仅 hourly 可省） | `TasksView.vue:715-736` | ⚠️**功能性信任 bug**：现在时区只在 hourly 显示、对 daily/weekdays 隐藏，但时区照样提交——「每天 09:00」会静默按 Asia/Shanghai 跑，UTC 用户无从察觉/修改。这是错时运行，非纯外观。 |
| 2 | **破坏性确认按钮改红** `confirmButtonClass:'el-button--danger'` | 所有 `ElMessageBox.confirm`（WorkbenchView/TasksView/FileSidebar/InspectorPanel） | 现在「删除」按钮是绿色（=肯定色），级联删文件时极易误点。封一个 `confirmDestructive()` helper 统一。 |
| 3 | **转后台任务成功后给去处** | `WorkbenchView.vue:151-162` | toast 加「查看任务」动作或跳 `/tasks` 并选中新任务，补上断头路。 |
| 4 | **截断徽标写清行数** 「仅显示前 1,000 行（结果已截断）」 | `WorkbenchView.vue:350` | 现在只写「结果已截断」，用户不知上限=1000、也不知自己的 `LIMIT 5000` 被覆盖——数据工具的正确性/信任隐患。顺带统一 200 vs 1000 的默认。 |
| 5 | **ListPlus/Sparkles 加文字标签** | `WorkbenchView.vue:264-287` | 让「转后台任务」「AI 分析」可见；仅 `运行` 保留图标+文字主按钮。 |
| 6 | **空态放一个 `type=primary` 的「上传文件」按钮 + 状态感知文案** | `WorkbenchView.vue:415-419`、`FileSidebar.vue` | 0 文件时文案改「上传第一个数据文件开始分析」并可点；把次要空态降噪。 |
| 7 | **两个搜索框补焦点环** `:focus-within` | `style.css:1207-1233`（sidebar/task search） | 现在 `outline:0` 覆盖了全局焦点环，键盘用户完全无反馈（WCAG 2.4.7）。照抄已有的 `.agent-table-search:focus-within`。 |
| 8 | **字重收敛到 400/500/600/700** | 全局 | 620/630/650→600、720/750→700，让层级在中文上真正可见。 |
| 9 | **禁用的发送/SQL 按钮给动态原因 tooltip** | `AiAssistantPanel.vue:105-110,968-990` | 现在静默置灰、四种原因都不说，用户不知是坏了/在加载/等他操作。 |
| 10 | **顶栏当前分区用绿色高亮 + `aria-current`** | `AppShell` 顶栏导航 | 现在选中态太弱；顺手给辅助技术暴露当前页。 |

> 第 1、2、4 条既是 UX 也是**正确性/信任**问题，无论是否做整体优化都建议先修。

## 四、高优先级明细（22 条，按主题归并）

### 信息架构与导航
- **转后台任务断头路**（S）`WorkbenchView.vue:151-162` — 见快速见效 #3。
- **AI 独立整页路由，割裂流程且重复选表模型**（L）— 见主题 T4。建议：把 AI 做成工作台内的侧滑面板（像检查器），让 SQL/结果/对话共存；并让 `agentTableBindings` 默认由 `queryBindings` 播种（可显式覆盖），消除两套选表。

### 首次运行与空态
- **中心空态不可操作且文案误导**（M）`WorkbenchView.vue:415-419` — 见 T2。文案随 `sources.length===0` 切换，并接一个真按钮触发上传。
- **上传是无标签纯图标按钮**（S）`FileSidebar.vue:306-323` — 见快速见效 #6。

### 核心分析流程
- **工具栏核心次级动作是费解图标**（S）`WorkbenchView.vue:264-287` — 见快速见效 #5。
- **截断警告隐藏真实行上限**（S）`WorkbenchView.vue:350` / `workspace.ts:392` — 见快速见效 #4。
- **建后台任务弹窗：无日程、无结果去向、无跳转**（M）`WorkbenchView.vue:145-168` — 弹窗内说明结果去哪、预计时长；成功后可跳转；后台任务导航项带运行计数。

### 视觉层级与排版
- **字号触底 9–10px（中文界面）**（M）— 见 T1。建 3–4 级字号、CJK 正文硬下限 12px、密度靠行高/内距而非缩字。
- **空态主操作是灰字、次级图标按钮却最抢眼**（M）— 给空态真正的绿色主按钮，上传图标降为 ghost。
- **自造字重梯在中文字体上无法区分**（S）— 见快速见效 #8。

### 反馈与系统状态
- **破坏性确认按钮渲染成安全/主色**（S）— 见快速见效 #2。

### 表单与输入
- **依赖时区的预设反而够不到时区选择**（S）`TasksView.vue:715-736` — 见快速见效 #1（功能 bug）。
- **无内联校验，所有表单提交时一句模糊 toast**（M）`TasksView / AiSettingsDialog / 导入弹窗` — 用 `el-form :model + :rules + prop` 出内联错误并滚动/高亮首个非法字段。

### AI Agent
- **应用/运行候选 SQL 把用户弹出 Agent 页**（L）`AgentView.vue:31,46` — 「应用」应就地（在 Agent 页内嵌/旁置查询面），仅「应用并运行」在必要时跳转，且保留对话滚动/时间线。
- **发送/SQL 按钮静默禁用无原因**（S）— 见快速见效 #9。
- **改选表冻结整个输入框、逼分叉**（M）`AiAssistantPanel.vue:1062` — 保持可打字，仅在发送时确认分叉；首次发送自动分叉 + 轻量提示 + 撤销。

### 后台任务与调度
- **时区仅在 hourly 显示、对 daily/weekdays 隐藏**（S）— 与快速见效 #1 同源，重复命中，务必修。

### 可访问性
- **侧栏/任务搜索框无可见焦点指示**（S）`style.css:1224-1233` — 见快速见效 #7。
- **浅色 `--subtle` 在小字号下对比不达标**（M）— 调深到约 `#5f6d67`（≈4.6:1），并把 8–9px 等宽用法提到 ≥11px。

### 一致性与设计系统
- **字号梯是 12 级微缩、无 token，正文常驻 9–11px**（L）— 定 5–6 级 `--fs-*` token 并全量映射，8–9px 说明文字抬到 10–11px 下限。
- **同一分段控件实现了 4 种**（M）— 统一成一个 `.seg`/包装 `el-segmented`，下划线仅留给页级页签。
- **图标按钮 8 种 bespoke 类 + 原生/el 混用**（L）— 收敛为两个尺寸(28/24px)一个类，选定单一按钮基元。

## 五、中 / 低优先级（择要）

**中优先级（33 条）常见项**：工作区身份 chip 无效且 landmark 标签与导航冲突；缺面包屑/页内定位/`document.title`；三处空态无引导且缺「支持格式」提示与示例数据；导入范围需额外「应用」round-trip 且「待应用」态易漏；多 Sheet 导入只绑一张；别名输入无可编辑提示/无校验去重；前台长查询阻塞且不可取消；停止运行中任务无确认（删除完成任务却要确认，模型不一致）；自定义 cron 无校验、列表里给用户看裸 6 段 cron 无「下次运行」预览；上下文分散三处；时间线只显工具步骤、藏了推理；失败但已出助手消息的 Run 无重试入口；日程页从不自动刷新（下次运行时间/暂停态静默过期）；浅色主题未把 Element 组件接入 token 系统；绿/蓝双强调色无规则；搜索框造 4 个 bespoke 版本。

**低优先级（19 条）常见项**：预览刷新按钮从不禁用且每次点都弹成功 toast；本地同步编辑动作也弹成功 toast、稀释信号；`clearApiKey` 与 API Key 输入可矛盾设置；`aria-live=polite` 套在整条流式消息列表上会刷屏辅助技术；候选 SQL 预览截断上限在管线各处不一致；`/` 命令提示过度承诺（只有一个命令）；结果分页缺行区间/页大小/跳页；排队任务的 0% 进度条与卡住的运行任务无法区分；查询「绑定 chip」是仅鼠标可点的 div；工作台页签 ARIA tabs 模式不完整；Lucide 图标用了 11 个随意尺寸、无隐喻分层；圆角用了 6 个值无层级逻辑。

## 六、建议的落地顺序

1. **第一批 · 快速见效（1–2 天）**：本文第三节 10 条。先修 3 个「功能/正确性」项（日程时区、破坏性按钮配色、截断行数），其余是高性价比可发现性/可读性修复。
2. **第二批 · 可读性与设计 token（半周）**：落 `--fs-*` 字号 token（CJK 下限 12px）+ 字重收敛 + `--subtle` 对比修复 + 圆角/间距/图标尺寸 token 化。这一步把 T1、T5 的地基打好，后续所有组件受益。
3. **第三批 · 组件统一（半周）**：抽 `.seg` 分段控件、统一图标按钮与搜索框、明色 Element token 接入。消除「多组件拼装感」。
4. **第四批 · 结构性（1 周+，需先脑暴对齐）**：AI 从整页路由改为工作台内侧滑面板 + 统一选表模型（T4）；空态/首运引导（示例数据、格式提示）；调度可读化（友好文案 + 下次运行预览 + 内联校验）。
