# 08 开发规划

## 阶段总览

| 阶段 | 周期 | 目标 | 退出标准 |
| --- | --- | --- | --- |
| Phase 0: 发现与原型 | 2 周 | 明确用户、流程、技术风险 | 可演示端到端原型和最终 MVP 范围 |
| Phase 1: 平台基础 | 4 周 | 搭建控制平面和基础资源 | 用户、工作区、数据源、对象存储、基础 API 可用 |
| Phase 2: 分析执行 MVP | 6 到 8 周 | 完成上传、脚本运行、运行历史 | 文件到脚本运行闭环稳定 |
| Phase 3: 调度与报表 | 6 周 | 完成定时执行和基础报表 | 用户可发布定时刷新的报表 |
| Phase 4: Beta 和治理 | 6 到 8 周 | 权限、审计、通知、配额、稳定性 | 5 到 10 个试点团队可用 |
| Phase 5: GA/企业化 | 8 到 12 周 | 私有化、SSO、成本、连接器扩展 | 可对外销售和部署 |

## Phase 0: 发现与原型

任务:

- 访谈 8 到 12 位目标用户。
- 验证核心使用场景: 文件到定时报表、数据库到团队报表。
- 做低保真产品流程和信息架构。
- 验证 Docker Runner 执行 Python/SQL 的最小原型。
- 验证 DuckDB 读取上传文件和生成 Parquet。

产出:

- 用户画像和痛点优先级。
- MVP 范围冻结。
- 技术风险清单。
- 端到端 demo。

## Phase 1: 平台基础

任务:

- Next.js 应用骨架。
- FastAPI 服务骨架。
- PostgreSQL schema 和迁移。
- 登录、工作区、成员和角色。
- 对象存储接入和 presigned upload。
- 数据源和文件元数据。
- CI/CD、测试、基础日志。

退出标准:

- 用户可登录、创建工作区、上传文件。
- 管理员可邀请成员。
- API 有基础鉴权和租户隔离测试。

## Phase 2: 分析执行 MVP

任务:

- SQL/Python 编辑器。
- 项目、草稿、保存版本。
- Scheduler Service、Redis Queue 和 Runner Worker。
- Docker 运行镜像和容器资源限制。
- DuckDB/Pandas 文件读取。
- 运行状态、日志、错误摘要。
- 运行产物写入对象存储。
- 基础资源限制和超时。

退出标准:

- 用户上传 CSV 后能写脚本并成功运行。
- 用户能看到日志、结果表和失败原因。
- 用户代码失败不影响控制平面。

## Phase 3: 调度与报表

任务:

- schedule 创建、暂停、恢复、删除。
- cron/interval、时区、重试、并发策略。
- 报表编辑器和栅格布局。
- 指标卡、表格、折线图、柱状图、Markdown。
- 报表发布、权限、最近成功快照。
- 失败通知。

退出标准:

- 用户能设置每日任务并自动刷新报表。
- 报表可分享给工作区成员。
- 调度运行有完整历史和日志。

## Phase 4: Beta 和治理

任务:

- 数据库连接 PostgreSQL/MySQL/ClickHouse 外部只读源，以及 S3/MinIO 文件快照导入与刷新已实现；云数仓连接器后续接入。
- 当前 MVP 已实现数据源 `view`/`query`/`manage` 授权、私有成员共享、字段分类与非管理者导出脱敏，以及派生项目/运行/报表/通知/审计的访问收敛；后续补组织级、源数据库行列级和外链策略。
- 当前 MVP 已提供数据源到草稿/发布项目版本、调度、可见报表和历史运行的影响分析；后续扩展字段级血缘和跨数据源图谱。
- RBAC 完善。
- 审计日志。
- 当前 MVP 已实现外部 Secret 引用、项目绑定快照和日志/结果脱敏；后续接入 KMS、动态凭证和轮换。
- Docker 网络隔离、rootless Docker 或 gVisor 可选增强。
- 成本和资源用量面板。
- 报表订阅和邮件通知。
- 性能和稳定性压测。

退出标准:

- 支持至少 5 个试点团队。
- 无已知 P0 安全问题。
- 平台调度触发成功率达 99%。

## Phase 5: GA/企业化

任务:

- SSO/OIDC。
- 单机 Docker Compose 部署包，企业版再提供 Helm Chart。
- 备份恢复和升级流程。
- 更多数据源连接器。
- 报表导出 PDF/PNG/CSV。
- API token 和嵌入报表。
- 数据血缘和发布审批。
- 安全和合规文档。

退出标准:

- 可签首批付费客户。
- 有标准部署文档和运维手册。
- 有安全白皮书和 SLA 草案。

## 团队配置建议

MVP 期最小团队:

- 1 名产品经理。
- 1 名设计师。
- 2 名前端工程师。
- 2 名后端/平台工程师。
- 1 名数据平台/基础设施工程师。
- 1 名 QA 或测试开发，可由工程师兼职但不建议长期缺位。

Beta 后增加:

- 安全工程师或安全顾问。
- DevOps/SRE。
- 数据连接器工程师。
- 客户成功/解决方案工程师。

## 风险登记

| 风险 | 概率 | 影响 | 预案 |
| --- | --- | --- | --- |
| 执行隔离复杂度超预期 | 高 | 高 | Phase 0 单独验证 Docker Runner、资源限制和网络隔离 |
| 报表编辑器范围膨胀 | 中 | 高 | MVP 使用固定组件和栅格布局 |
| 数据源需求发散 | 高 | 中 | 连接器 roadmap 分级，文件和少数数据库优先 |
| 成本不可控 | 中 | 高 | 配额、超时、缓存、成本面板从 Beta 开始做 |
| 用户把产品理解为 BI | 中 | 中 | 文案和 onboarding 强调脚本生产化 |
| 私有化部署拖慢 SaaS | 中 | 中 | 先统一 Docker Compose 和环境变量配置，后续再抽象 Helm |
