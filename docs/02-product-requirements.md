# 02 产品需求文档

## 产品目标

AnyDatas 的目标是让数据工作者在一个在线工作区内完成以下闭环:

1. 接入数据源。
2. 编写分析逻辑。
3. 手动或定时执行。
4. 审核运行结果。
5. 发布和订阅报表。

## 用户角色

| 角色 | 主要诉求 | 成功体验 |
| --- | --- | --- |
| 数据分析师 | 快速处理数据、复用脚本、自动刷新报表 | 不再依赖本地电脑和手工导出 |
| 业务负责人 | 查看可信报表、订阅异常变化 | 每周/每日自动收到最新指标 |
| 数据平台工程师 | 管理数据源、权限、资源和稳定性 | 用户自助分析不破坏基础设施 |
| 管理员 | 成员、账单、审计、安全策略 | 能看见谁访问了什么、跑了什么 |

## 核心用户旅程

### 旅程 1: 文件到定时报表

1. 用户创建项目。
2. 上传 CSV 或 Excel。
3. 系统推断 schema，展示数据预览和字段类型。
4. 用户编写 SQL/Python 处理逻辑。
5. 用户运行脚本，查看日志和输出表。
6. 用户选择输出字段生成图表和指标卡。
7. 用户设置每日 09:00 刷新。
8. 系统自动运行，失败时通知，成功后更新报表快照。

### 旅程 2: 数据库到团队报表

1. 管理员配置 PostgreSQL/ClickHouse/Snowflake 连接。
2. 数据分析师创建只读查询项目。
3. 用户编写参数化 SQL，使用 Python 做清洗或建模。
4. 用户发布 Dashboard，设置部门成员可见。
5. 业务负责人订阅每周邮件或站内通知。

### 旅程 3: 调度任务治理

1. 管理员查看所有定时任务。
2. 系统展示运行频率、耗时、失败率、资源消耗。
3. 管理员暂停高成本或失败频繁任务。
4. 用户收到原因和恢复建议。

## 功能范围

### P0: MVP 必须具备

- 组织、工作区、成员、角色。
- 文件上传: CSV、XLSX、Parquet。
- 数据预览、schema 推断、字段类型修改。当前 MVP 已支持字段类型、描述、样本和质量摘要的 Schema 页面；类型修改是元数据声明，不重写原始文件。
- 数据库连接: PostgreSQL 和 MySQL 优先，ClickHouse 可作为第三个。
- SQL 编辑器和 Python 脚本编辑器。
- 手动运行、停止运行、查看日志、查看输出。
- 定时任务: cron、interval、时区、启停、重试、超时。
- 运行历史: 状态、耗时、触发方式、代码版本、输入数据、产物。
- 报表: 指标卡、表格、折线图、柱状图、饼图、筛选器、Markdown 文本。
- 报表权限: 当前 MVP 支持工作区可见，以及私有报表的指定成员授权；后续再扩展独立角色和外链策略。
- 通知: 运行失败站内通知，以及报表订阅者的定向刷新成功/失败站内通知；邮件可作为 P0 后段。
- 基础审计: 登录、数据源创建、脚本运行、报表发布、权限变更。

### P1: Beta 增强

- 数据源连接器扩展: Snowflake、BigQuery、S3、Google Sheets。
- 项目版本管理和发布版本。
- 运行参数和表单输入。
- 报表订阅: 邮件、Webhook、Slack/Teams。
- 报表快照、PDF/PNG 导出。
- 环境管理: requirements.txt、预置镜像、包安装缓存。
- 成本和资源面板。
- 数据血缘: 报表到脚本、脚本到数据源。
- API token 和嵌入式只读报表。

### P2: 企业化和规模化

- SSO/OIDC、SCIM、细粒度 RBAC。
- 行级权限和列级脱敏。
- 高级连接器市场。
- Notebook 多 cell 体验和协作编辑。
- Git 同步、代码审查、审批发布。
- 多区域部署、灾备、租户级密钥管理。
- AI 辅助 SQL、图表建议、异常解释。

## 非功能需求

| 类别 | 要求 |
| --- | --- |
| 可用性 | 控制平面目标 99.5% 起步，Beta 后提升到 99.9% |
| 调度可靠性 | 已启用计划在平台可用时按计划触发成功率大于 99% |
| 安全 | 用户代码隔离运行，默认无跨租户、无未授权网络和密钥访问 |
| 性能 | 100MB 文件上传后 30 秒内完成预览；常规报表 3 秒内打开缓存结果 |
| 可观测 | 每次运行有日志、指标、事件、资源用量和失败原因 |
| 可扩展 | 执行任务水平扩展，控制平面无状态化 |
| 可恢复 | 元数据每日备份，关键对象存储启用版本或生命周期策略 |

## 产品指标

| 指标 | 口径 | 目标 |
| --- | --- | --- |
| 首次成功运行时间 | 新用户注册到第一次脚本成功运行 | 小于 30 分钟 |
| 周活跃工作区 | 一周内有运行或报表查看的工作区 | 持续增长 |
| 定时任务成功率 | 平台触发并完成的任务占比，排除用户代码逻辑错误可单独统计 | 大于 95% 起步 |
| 报表消费率 | 报表被非作者查看的比例 | 大于 50% |
| 失败恢复时间 | 失败任务从告警到用户定位原因 | 日志和错误摘要 1 分钟内可见 |

## 关键产品决策

- 分析项目采用“脚本 + 产物”模型，先不做完整多人实时 Notebook。
- 定时运行只运行已保存版本，避免草稿代码影响生产报表。
- 报表默认绑定最近一次成功运行快照，避免打开报表时触发长时间计算。
- 用户代码默认不能访问公网，除非管理员开启 egress allowlist。
- 密钥以引用方式注入运行环境，永远不回显给前端。
